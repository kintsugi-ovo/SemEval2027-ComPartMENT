## 1. DeBERTa 出了什么问题：train loss 自己反弹了

**统一口径**：每轮结束时的 train loss（`ceil(epoch)` 分组 + 取该轮最后一个采样点）。
v1 的 `logging_steps` 稀疏（每轮 1–2 条，落在轮末）、v2 加密（每轮 8 条，落在轮内），
不统一口径会误读成"v2 一开始 loss 就更高"。

| 运行 | v1（3 轮） | v2（single 3 轮 / joint 5 轮） | 判定 |
|---|---|---|---|
| `single_en-nn` | 0.461 → 0.292 → 0.201 | 0.412 → 0.353 → **0.179** | ✅ 健康（v2 甚至更低） |
| `single_de-nn` | 0.464 → 0.354 → 0.241 | 0.516 → 0.424 → **0.452 ↑反弹** | ❌ **崩** |
| `single_en-pv` | 0.502 → 0.394 → 0.388 | **0.628 → 0.599 → 0.580（全程不降）** | ❌ **崩** |
| `single_de-pv` | 0.538 → **0.546 ↑反弹** → 0.494 | 0.533 → 0.553 → 0.508 | ⚠️ **v1 也有同样的病** |
| `joint` | 0.545 → 0.441 → 0.342 | 0.600 → 0.585 → **0.661 → 0.664 → 0.804 ↑** | ❌ **崩** |

### 1.1 这排除了什么

train loss 反弹 ⇒ **不是**下列任何一种：

| 曾经的解释 | 排除依据 |
|---|---|
| 过拟合 / 泛化变差 | 过拟合的表征是 **train loss 继续降、eval 指标变差**；这里是 **train loss 自己上升** |
| 评测口径错 / 指标算错 | 指标错不会让训练损失上升；而且 Qwen 用同一套指标代码 5/5 健康 |
| 数据管线错 / 切分泄漏 | 两版数据管线一字未改（18 项口径清单一致），且 Qwen 侧完全正常 |
| 模型权重没加载 / 初始化错 | 随机初始化的 eval 指标两版**逐位相同**（e0: −0.003/0.064/1.554），说明数据与评测一致，差异全部来自训练过程 |

### 1.2 这确认了什么

**优化过程真的崩了**（loss 上升 + eval_loss 0.644→1.057 + 指标 1 从 0.200 掉到 −0.099）。

配套的梯度信号（每轮内 grad_norm 最大值）：

| 运行 | v1（med / max / >50 的次数） | v2（med / max / >50 的次数） |
|---|---|---|
| DeBERTa `joint` | 11.9 / 12.2 / **0** | 18.3 / **231** / **5** |
| DeBERTa `single_en-pv` | 13.9 / 106 / 1 | 15.5 / **548** / **5** |
| DeBERTa `single_en-nn`（健康） | 22.9 / 28 / 0 | 15.9 / **492** / 2 |
| Qwen `joint` | 2.4 / 27 / 0 | 6.3 / 45 / 0 |

⚠️ **尖峰不是充分条件**：`single_en-nn` 在 v2 出现了 492 的尖峰，却依然健康收敛。
所以尖峰是**伴随现象**，不能单独用来判"会不会崩"。

## 2. 崩塌的根因：DeBERTa 本来就站在刀刃上

### 2.1 最强证据：v1 也会得同样的病

`v1 · DeBERTa · single_de-pv` 的完整轨迹：

- **train loss**：0.538 → **0.546（反弹）** → 0.494（不降）
- **grad_norm**：第 1 轮 **158.1**（v1 其余运行只有 5–17）
- **指标 1**：0.0776 → **−0.0067 → −0.1239**（第 2 轮转负）
- **指标 2**：0.378 → 0.049 → 0.206（同步塌陷）

而 v1 的配置是 **μ=0、δ=1.0、warmup=0.1、3 轮**——**v2 的任何一项改动都不在这里**。

⇒ **同一种病在 v1 就存在**。所以：

| 版本 | 崩溃运行数 | 发病率 |
|---|---|---|
| v1 | 1 / 5（`single_de-pv`） | 20% |
| v2 | 3 / 5（`single_de-nn`、`single_en-pv`、`joint`） | 60% |
| Qwen v1 | 0 / 5 | 0% |
| Qwen v2 | 0 / 5 | 0% |

⇒ **v2 没有"制造"这个 bug，只是改变了落点。**

### 2.2 学习率：single 的崩塌**不能**用"lr 更高"解释

各轮**结束时**的学习率（跨版本公平口径）：

| 运行 | v1 | v2 | 谁更高 |
|---|---|---|---|
| `single_de-nn` | 1.67e-5 → 8.38e-6 → ~0 | 1.42e-5 → 7.29e-6 → ~0 | **v1 更高** |
| `single_en-pv` | 1.67e-5 → 8.42e-6 → ~0 | 1.43e-5 → 7.58e-6 → ~0 | **v1 更高** |
| `joint` | 1.67e-5 → **8.35e-6** → ~0 | 1.68e-5 → **1.26e-5** → 8.42e-6 → 4.22e-6 → 0 | **v2 高 1.51×（第 2 轮）** |

- **single 运行**：v2 因 `warmup_ratio` 从 0.1 缩到 0.05（提前进入衰减段），
  **同一轮末的 lr 反而比 v1 低约 14%**，可它们照样崩 ⇒ **single 的崩塌与 lr 无关**。
- **joint 运行**：`JOINT_EPOCHS` 从 3 提到 5，把**高 lr 暴露期从第 1 轮延长到第 2 轮**
  （第 2 轮末 lr 从 8.35e-6 抬到 1.26e-5，**1.51 倍**），
  而 DeBERTa joint **恰好在第 2 轮崩** ⇒ `JOINT_EPOCHS=5` 是 joint 崩塌的**放大器**（不是根因）。

### 2.3 头号嫌疑：`MU_STD` 的损失项与主损失**方向相反**

日志启动处打印的**分项损失**（两个模型同值，因为是同一段演示代码）：

```
L_huber = 0.2862   绝对值误差
L_std   = 1.8450   组内离散程度（人工组内 std=3.0，预测组内 std=1.5 → 被罚）
```

- `μ = 0.05` ⇒ `μ·L_std = 0.092`，占总损失（0.286+0.092=0.378）的 **24%**。
- 这是**随机初始化状态下**的值 ⇒ `L_std` 一开始就是一项**量级大、且尚未被优化**的损失。

**两条硬伤**：

1. **目标错配**：这个损失惩罚的是「组内 std 的**绝对值**偏离人工 std」，
   而**指标 2 要的是「组内 std 随语境变化的*趋势*与真值相关」**。
   把每个目标的 std 调准到 3.0，和"std 随语境起伏的方向对不对"是两件事。
   实测印证：Qwen joint 指标 2 **−0.022**（噪声内，零收益），DeBERTa 直接崩。
2. **早期与主损失对抗**（机制假说，**推断**）：模型早期容易先塌缩到"近似常数预测"
   （此时预测组内 std 很小，log 打印的 1.5 就是这个状态），
   `L_std` 便持续给出「把同组样本彼此推开」的梯度，而 `L_huber` 要「都预测到真值」——
   **两者方向相反 → 拉锯 → 震荡 → train loss 反弹**。
   Qwen 容量足够大，能先满足 `L_huber`，`L_std` 随之被满足，所以它不发病。

**支持这一假说的一个数字**：`v2 · single_de-nn` 的 train loss 卡在 **0.45–0.52**，
而 v1（μ=0）最低做到 **0.241**。也就是说 **v2 连"绝对值预测得准"这件事都没学到**，
这与"有一项非主目标的梯度一直在拉"完全吻合。

## 3. v2 的 4 项超参改动：逐项判定

| # | 改动 | v1 → v2 | 实测结果 | 判定 |
|---|---|---|---|---|
| 1 | `MU_STD` | 0 → 0.05 | 目标（指标 2 提升）**完全没兑现**（Qwen joint −0.022，噪声内；DeBERTa 崩）；**DeBERTa 吞吐 −21%~−40%**；**头号嫌疑**（§2.3） | ❌ **回滚为 0** |
| 2 | `HUBER_DELTA` | 1.0 → 2.0 | Qwen 与 v1 无差别（噪声内）；DeBERTa 3/5 变差。**无任何收益证据** | ❌ **回滚为 1.0**（无收益不留） |
| 3 | `WARMUP_RATIO` | 0.1 → 0.05 | 效果是"提前进入衰减段"（single 各轮末 lr 反而低 14%），**没有换来任何指标收益**；对已知敏感模型是风险项 | ❌ **回滚为 0.1** |
| 4 | `JOINT_EPOCHS` | 3 → 5 | Qwen：0.4950→0.4999，**噪声内**（说明第 3 轮已到平台）；DeBERTa：**把第 2 轮的高 lr 暴露期拉长 1.51×**，恰是它崩溃的那一段 | ❌ **回滚为 3**（若同时降 lr 才可加到 5–6） |
| 5 | `metric_for_best_model` | 指标1 → 综合分 | **唯一正收益**：DeBERTa joint 从 epoch5 的 −0.0137 救到 epoch1 的 **+0.2002**（Δ0.214 ≫ 阈值 0.065）。**但它自身有缺陷**（§5.2），且在 Qwen 侧选错了 2 次 | ✅ **保留，但必须改定义** |
| 6 | 组内损失无效列护栏 | 无 → 有 | 正确工作，**无负面影响** | ✅ 保留（但随 μ=0 一并失去意义） |

> **总账：4 项超参改动，Qwen 侧 0 收益 / DeBERTa 侧 3/5 显著负收益。**
> 这是一次**负收益的迭代**，唯一留下的价值是第 5 项的选择机制。

## 4. 轮次与学习率设置是否合理

### 4.1 Qwen（当前唯一可用的主线）

| 判据 | 数据 | 判定 |
|---|---|---|
| lr 2e-5 够不够稳 | v1/v2 **各 5/5 运行健康**，train loss 能压到 0.041 | ✅ **合理，不要降**（降了只会更欠拟合） |
| 轮数够不够 | 指标 1 逐 epoch：0.390→0.396→0.481→0.489→**0.500**，增量 +0.006/+0.085/+0.008/**+0.011**；指标 2：0.146→0.307→0.342→0.363→**0.365** | ✅ **已到平台**。再加到 8 轮，预期收益 ≤ 0.01 ≪ 阈值 0.065 |
| train loss | 0.460→0.226→0.145→0.067→**0.041**（**降 91%**）而指标 1 只涨 0.11 | ⚠️ **已过拟合**：继续训练只会更贴训练集 |

⇒ **Qwen 的轮次与 lr 都不需要动。** v2 把 joint 改成 5 轮，
训练时长 **DeBERTa 68.3 → 180.8 min（2.65× = 轮数 1.67× × μ 带来的吞吐损失 1.59×）**、
**Qwen 139.0 → 225.6 min（1.62×）**，
换来的是噪声内的 +0.005 —— **不划算**。

### 4.2 DeBERTa

| 判据 | 数据 | 判定 |
|---|---|---|
| lr 2e-5 | 同 lr 下 DeBERTa 崩 1/5（v1）、3/5（v2），Qwen 0/10 | ⚠️ **偏大**，建议 **1e-5**（两条基线同步改，见 §7） |
| 轮数 3 | v1 joint 指标 1：0.038→0.223→**0.379**，第 2→3 轮 Δ0.156 ≫ 阈值 0.065 ⇒ **欠训练** | ⚠️ 3 轮不够，但**必须先降 lr**再补到 5–6 轮（否则 5 轮 = 更长的高 lr 暴露期） |
| best-checkpoint | 已能救回崩溃后的最好轮次 | ✅ 保留 |

## 5. Qwen 的 v2 相对 v1：变好还是变坏？

### 5.1 逐运行对比（阈值：指标1 0.065 / 指标2 0.153 / RMSE 0.046）

| 运行 | v1 指标1/指标2/RMSE | v2 指标1/指标2/RMSE | Δ指标1 | Δ指标2 | 判定 |
|---|---|---|---|---|---|
| `single_en-nn` | 0.4692 / 0.1925 / 0.8423 | 0.4168 / 0.1369 / 0.9163 | −0.052 | −0.056 | ✅ 噪声内 |
| `single_de-nn` | 0.5035 / 0.2512 / 0.7707 | 0.4620 / 0.3871 / 0.7976 | −0.042 | +0.136 | ✅ 噪声内 |
| `single_en-pv` | 0.4989 / 0.6574 / 0.9525 | 0.4781 / 0.7335 / **1.2070** | −0.021 | +0.076 | ⚠️ 指标噪声内，**RMSE 显著变差 +0.255**（成因见 §5.2，**不是超参的锅**） |
| `single_de-pv` | 0.3795 / 0.3317 / 1.2004 | 0.4037 / 0.4990 / **1.0010** | +0.024 | +0.167 | ✅ 指标1 噪声内；指标 2 +0.167 刚过阈值；**RMSE 显著变好 −0.199** |
| **`joint`（提交用）** | 0.4950 / 0.3864 / 0.8429 | **0.4999** / 0.3648 / 0.8459 | +0.005 | −0.022 | ✅ **全部在噪声内 ⇒ 无变好也无变坏** |

**总账：Qwen 上 v2 的超参改动 = 0 收益。**
两个方向相反的显著差异（en-pv RMSE 变差、de-pv RMSE 变好）都来自**选择机制**，
不是超参本身。

### 5.2 唯一的显著退化来自 best-checkpoint 机制的设计缺陷

Qwen `single_en-pv` 的逐 epoch：

| epoch | 指标1 | 指标2 | RMSE | 综合分 = 指标1+指标2 |
|---|---|---|---|---|
| 1 | 0.482 | **0.734** | **1.207** | **1.212 ← 被选中** |
| 2 | 0.516 | 0.616 | 0.984 | 1.132 |
| 3 | **0.491** | 0.675 | **0.973** | 1.166 |

**根因：综合分把两个噪声量级差 2.4 倍的分量等权相加。**

| 分量 | 差值 SD（bootstrap） | 本例中该分量的差 | 是否超过其自身噪声 |
|---|---|---|---|
| 指标 1 | 0.023 | 0.009（e1 vs e3） | ❌ 噪声内 |
| 指标 2 | **0.055** | 0.059（e1 vs e3） | ⚠️ 刚好在噪声内 |
| RMSE | 0.017 | 0.234（e1 vs e3） | ✅ **显著** |

⇒ **一个纯噪声级的指标 2 差（0.059）压过了指标 1 的 0.009，选中了随机优胜者**，
而这个 checkpoint 的 RMSE 显著更差（1.207 vs 0.973，Δ0.234 > 阈值 0.046）。

**修法（比"综合分 = 指标1 + 指标2 − RMSE/5"更严谨）**：**按各分量的噪声 SD 归一化**，
即在 z 分数空间里做和：

```
综合分 = 指标1/0.023 + 指标2/0.055 − 指标3/0.046
```

逐次复算 Qwen `single_en-pv`：

| epoch | 综合分（新） |
|---|---|
| 1 | 20.96 + 13.35 − 26.24 = **8.07** |
| 2 | 22.43 + 11.20 − 21.39 = **12.24** |
| 3 | 21.35 + 12.27 − 21.15 = **12.47 ← 选中** |

⇒ 改选 epoch 3，**RMSE 1.207→0.973、指标1 0.478→0.491，两项同时变好**。
（其余 9 次运行的选中轮次不变；DeBERTa joint 仍选 epoch 1 ✓）

### 5.3 Qwen 逐设置的短板在哪（v2 joint 交出模型）

|---|---|---|---|
| en-nn·ModAvg | 0.478 | **0.149** | **指标2 最弱** |

## 6. "单纯微调还能不能提升"：瓶颈不在训练，在输入

**证据**：Qwen v2 joint 的 **train loss 降了 91%（0.460→0.041），指标 1 只涨了 0.11（0.390→0.500）**。
训练侧已经没有未开发的空间；而指标 1 距 type-level oracle 仍差 **0.289**（远大于阈值 0.065），
说明**信息还在，只是模型看不到**。

两个已实测的输入缺口，正好对应两个最弱设置：

| 缺口 | 实测事实 | 对应指标 | 交付物 |
|---|---|---|---|
| **de-nn 没有 Mod/Head 边界** | 德语复合词 **100% 连写**，Mod 只是前缀（95.9%），Head 是后缀且有音变融合（`Ablage+Fläche`→`Ablagefläche`）→ 模型无法知道哪段是修饰语 | `de-nn·ModAvg` 指标1 仅 0.318（Qwen）/ 0.118（DeBERTa），而 `de-nn·HeadAvg` 有 0.688 / 0.222 | **交付物 9：`de-nn` 预切分模块** |
| **pv 的 MWE 在 context 中找不到** | 变形 / 分离 / 连字符导致 **en-pv 67.1% / de-pv 79.2%** 的行定位不到目标 | 这些行**不可能"因句而异"** → 直接压低**唯一的出局线（指标 2）** | **扩展 pv 定位器**（S0–S5 级联已覆盖 88.6% / 77.8%，剩余 11.4% / 22.2% 待处理） |

⇒ **单靠调超参能拿到的增量 ≪ 0.065 的可检测阈值**（这已被 v1/v2 两轮共 20 次运行验证过两次）。
真正的提升顺序应该是：

1. **补输入信息**（de-nn 预切分 + pv 定位器）—— 空间最大，且是**唯一能撬动指标 2** 的方向
2. **降噪**（k 折交叉验证：按目标分 5 折 → 样本量 ×5 → 噪声 0.065 → 约 **0.029**）——
   这一条**不涨分，但让已有的差距变得可测**，是后续一切调参的前提
3. **换更强的主干**（需 ≥24GB 卡：Qwen2.5-3B 全参需 25.3 GiB，
   24GB 卡的 21.6 GiB 预算装不下全参；只能顶部 50% 冻结，或换更大的卡）
4. **微调内的微调**（lr / 轮数 / loss 权重）—— 收益已被证明在噪声内

> ⚠️ **一个必须避开的陷阱**：本项目存在**行序泄漏**（组内 `Spearman(ContextID, HeadAvg)` = 0.985/0.976，
> pv 更是 0.994/0.990）。
> 如果为了"聚合同目标多条例句"而把同一目标的其它例句喂进模型，会**同时引入 ContextID 的行序信号** →
> 指标能刷上去，但这是**作弊**，官方一查就能发现。
> ⇒ 若要做跨例句聚合，必须**把 ContextID 与语境解耦**（随机配对 / 打乱行序后配对），
> 且**绝不能把 ContextID 本身喂进模型**。

## 7. 应该怎么办（按优先级）

### P0-1｜先把 DeBERTa 的病定性（约 1.6 h，用已崩且最便宜的 `single_en-pv` 当平台）

**不要**直接再跑一次 3 小时的 joint 去"试试看"。

| 实验 | 配置 | 时长 | 回答什么 |
|---|---|---|---|
| **E0** | v1 配置（μ=0, δ=1, warmup=0.1），**只换 seed = 43 / 44** | ~10 min ×2 | **验证"DeBERTa 本来就脆"**（§2.1 已经给出强证据，这里做确认） |
| **E1** | v2 配置 + **lr 1e-5** | ~14 min | lr 是不是主因 |
| **E2** | v1 配置 + **lr 1e-5** | ~10 min | 分离"lr"与"其余三项改动" |
| **E3（新增）** | **v2 配置，但 `MU_STD = 0`**（其余同 v2） | ~10 min | **直接隔离头号嫌疑 `μ·L_std`**（§2.3 的假说） |

> E3 是本文新增的：v1↔v2 一次性改了 4 项，**现有日志无法归因到单一项**；
> E3 只动 μ 一项，是把 §2.3 的机制假说钉死的最短路径。

### P0-2｜零成本的三处修正（不需重训，改代码即可）

1. **综合分改为噪声归一化**：`指标1/0.023 + 指标2/0.055 − 指标3/0.046`（§5.2）——
   修掉"用噪声更大的分量主导模型选择"这个缺陷。
2. **回滚 4 项超参**：`MU_STD=0`、`HUBER_DELTA=1.0`、`WARMUP_RATIO=0.1`、`JOINT_EPOCHS=3`。
3. **主提交系统切到 Qwen**（5/5 健康、joint 0.4999），DeBERTa 在稳定性定性前只作对照。

### P0-3｜DeBERTa 的稳定化（等 E0–E3 的结果再选）

| 方案 | 做法 | 代价 |
|---|---|---|
| A（推荐） | **lr 2e-5 → 1e-5，两条基线同步改**，joint 补到 5 轮 | 重跑两条基线（并行 ≈ 6 h，串行 ≈ 10.8 h） |
| B（最根本） | **换 24GB 卡**（L4）→ Qwen 的 t2（Adafactor+AMP）装得下 → **能开 AMP**（数值缓冲 + 1.5–2× 速度） | 换实例，无代码改动 |
| C（兜底） | 只保留 best-checkpoint 机制，其余回滚 | ≈ 5 h，但不确定性仍在 |

### P1｜真正能涨分的（与超参无关）

| 优先 | 事项 | 预期 |
|---|---|---|
| P1 | **交付物 9：`de-nn` 预切分模块**（形态分析器 + 置信度） | 直接打 `de-nn·ModAvg`（0.318 / 0.118） |
| P1 | **扩展 pv 定位器**（剩余 11.4% / 22.2% 未定位） | 打唯一的出局线 指标 2 |
| P1 | **k 折交叉验证**（按目标分 5 折） | 噪声 0.065 → 0.029，让后续所有对比可测 |
| P2 | bootstrap CI 进 notebook（每个数字带误差棒） | 报告可信度 |

## 8. 一页纸总结

```
DeBERTa v2 的崩塌 = 优化过程崩溃（train loss 自己反弹），不是泛化、不是指标算错、不是数据管线。
  病根 = DeBERTa-v2-xlarge 在「fp32 + 无 AMP + Adafactor + lr 2e-5」下本来就脆
        （v1 的 single_de-pv 有完全相同的病：loss 反弹 + grad_norm 158 + 指标转负 −0.124）
  v2 的 4 项超参改动没有制造 bug，只是把发病率从 1/5 提到 3/5
  头号嫌疑 = μ·L_std（早期与主损失方向相反；日志实测 L_std=1.845，占损失 24%）
  放大器   = JOINT_EPOCHS=5（把第 2 轮高 lr 暴露期拉长 1.51×，恰是崩溃那一轮）

Qwen 的 v2 = 没有变好也没有变坏（joint Δ = +0.005/−0.022/+0.003，全在噪声内）
  唯一显著差异（single_en-pv RMSE +0.255）是 best-checkpoint 机制的缺陷，不是超参的锅
  Qwen 的 lr 2e-5 与轮数都合理；train loss 已压到 0.041，训练侧没空间了
  ⇒ 真正的瓶颈是输入信息（de-nn 连写没边界 / pv 定位失败），不是超参

v3 动作：回滚 4 项超参 + 综合分改噪声归一化 + 主线切 Qwen + 1.6 h 的 E0/E1/E2/E3 定性
        + 补 de-nn 预切分与 pv 定位器 + k 折 CV 降噪
```
