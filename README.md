## 1. 任务与目标

给定一个多词表达（复合词 `account book`、小品词动词 `crack down`）和一句真实语料例句，
输出该表达**在这句语境里**的组合性分数。覆盖四类设置：`en-nn` / `de-nn` / `en-pv` / `de-pv`，
复合词的修饰语（Mod）与中心语（Head）分别打分，小品词动词只打一个整体分。

**本仓库的目标**不是刷榜，而是把这条任务线上的三件事做扎实：

1. 跑通一条**可复现、口径可核对**的基线管线（两条主干共用数据处理、超参、指标与绘图，只切换 `MODEL_KEY` 一个变量）；
2. 用实测数据回答「这个任务到底难在哪、指标能到什么水平、哪些做法是死路」；
3. 把每一版的改动与**否证结论**都留在仓库里，避免同一批错误被反复重跑。

## 2. 指标及其意义

官方在**每个 language×subtask 设置**上算三个指标，再取跨设置平均。

| # | 指标 | 定义 | 意义 |
|---|---|---|---|
| 1 | **组合性相关 ρ**（主指标） | 逐例句 `Spearman(预测分, 人工分)` | 只看「谁比谁大」的顺序是否一致，不看差多少 |
| 2 | **语境方差相关 ρ**（次要指标，但一票否决） | 先按目标算预测分的 std，再算人工分的 std，最后跨目标 `Spearman` | 专抓「同一个 MWE 在所有例句上给同一个分」的假答案：此时组内 std ≡ 0，相关系数未定义 → **nan** → 榜单按 0 计，直接出局 |
| 3 | **RMSE**（补充） | 逐例句误差的均方根 | 唯一看绝对值的指标，惩罚整体校准偏差 |

六个评测设置：`en-nn·ModAvg`、`en-nn·HeadAvg`、`de-nn·ModAvg`、`de-nn·HeadAvg`、`en-pv·Avg`、`de-pv·Avg`；
「合计」= 这六个值的平均（nan 安全），**不是**把所有行拼起来算一个总 ρ。

> 三个指标分工可以这样记：指标 1 问「每句报得准不准」，指标 2 问「知不知道谁更吃语境」，指标 3 问「整体偏了多少度」。
> 一个「读懂语境但整体偏高」的系统，指标 2 可以拿满分而指标 1 几乎归零 —— 三个指标互补。

指标 2 的一个实用性质：它对**平移免疫**（预测整体加常数不改变组内 std），对**尺度不敏感**（噪声让 std 翻倍，秩几乎不变），
对**顺序敏感**。这既是它能识别「假答案」的原因，也是它在噪声下不稳定的原因。

## 3. 现在面临什么问题

以下每条都来自本仓库 `scripts/` 下的实测脚本（数据见 `reports/data_analysis.md`，图见 `reports/figures/`）。

**① 语境信号在名词复合词上极弱，四舍五入接近「看类型不看句子」。**
跨语境极差中位数：`de-nn` **0.70**、`en-nn` 1.40、`de-pv` 1.75、`en-pv` **2.30** —— 难度差近 20 倍，却被「合计」压成一个数。
`de-nn` 的组内真实信号方差为 **0.0000**（观测 0.1175 vs 噪声期望 0.1264）。

**② 标签噪声给指标 1 划了天花板。**
标签是 10 位标注者 0–5 分的均值，均值噪声 = `Std²/10`（不是 `Std²`）⇒ 指标 1 的 ρ 上限只有 **0.845–0.927**，
信噪比 2.51（en-pv，最脏）–6.10（de-nn Head，最干净）。人工组内 std 只有约 10–15% 是可复现方差。

**③ 指标 2 的金标准本身被目标级歧义度污染。**
nn 上 40–74% 的 gold 组内 std 来自「这个 MWE 本身就难说」，不是语境效应。
蒙特卡洛天花板（v3 报告口径）：`en-nn·Mod` 0.052、`en-nn·Head` 0.081、`de-nn·Mod` 0.001、`de-nn·Head` 0.002、
`en-pv` 0.413、`de-pv` 0.257。**nn 上指标 2 低是正常的，不该当失败项。**

**④ 指标 1 与 3 根本不强制使用语境。**
「每行填该目标的真实均值」的作弊上界：指标 1 可达 **ρ = 0.70–0.92**、RMSE 0.33–0.76，
但指标 2 全为 nan。⇒ 只有指标 2 在管「你是否真的因句而异」。

**⑤ 数据本身带行序泄漏，是一条现成的作弊通道。**
组内 `Spearman(ContextID, 分数)` 高达 **0.98–0.99**，且 100% 的目标 ρ > 0.5（`ModAvg` 列是随机序，说明泄漏编码的是中心语/整体贡献）。
后果：一个**完全不看文本**、只按组内秩输出的基线，在 `en-pv` 上拿 **ρ = 0.623**、`de-pv` **0.521**，
已追平已发表最好系统（ComposiGen 0.50）。逐行随机划分与 MWE 互斥划分都挡不住。
⇒ 载入后必须**先删 `ContextID`、再物理打乱**。

**⑥ 多词表达在句中的定位有硬缺口。**
级联定位（精确 → 转写还原 → 德语前缀屈折/后置分离 → 词干前缀 → 相邻窗口）之后：
`en-nn` 100%、`de-nn` 100%、`en-pv` **86.3%**、`de-pv` **77.7%**。
简单子串匹配会漏掉 66%–79% 的例句；剩下的 `de-pv` 22.3% 需要形态分析器。

**⑦ 样本量小到指标本身在抖。**
目标级 cluster bootstrap（800 次重采样）给出的最小可检测差：指标 1 **0.065**、指标 2 **0.153**、RMSE **0.046**。
下文所有「有收益 / 无收益」的判定都用这三个阈值。

**⑧ 德语复合词的成分边界不可还原。**
`Mod + Head` 直接拼接在 `de-nn` 只有 **59.1%** 能还原（其余 40.9% 带 Fugen-s：-s 25.2%、-n 8.0% 等）；
英德小品词动词的语序还相反（英 `Base + Particle`，德 `Particle + Base`）。

## 5. 三版实验与结论

两条主干全程保持一致：`microsoft/deberta-v2-xlarge`（885M 编码器，掩码均值池化）与 `Qwen2.5-1.5B-Instruct`（1.5B 解码器，末 token 池化），
共用同一套数据处理、同一组超参、同一套指标与绘图，只切换 `MODEL_KEY`。每版各跑 5 次运行
（`single_en-nn` / `single_de-nn` / `single_en-pv` / `single_de-pv` / `joint`），`joint` 覆盖全部 6 个评测设置。
硬件为 2×Tesla T4 14.56 GiB，全参微调 + Adafactor。

| 版本 | 做了什么 | 结论 |
|---|---|---|
| **v1** | 完整管线：反泄漏载入 → 级联定位 → 统一输入模板 → 回归头 `5×sigmoid` → Huber 损失 → 官方三指标 | 首次跑通 5×2 次运行，0 报错，指标 2 全非 nan。**最佳 Qwen joint = 0.4950 / 0.3864 / 0.8429**。暴露四个问题：德语 nn 修饰语列学不动（0.038，与随机初始化之差 0.041 < 阈值 0.065，等同没学）；小品词动词字面匹配缺口 67%/79%（级联后仍有 13.7%/22.3% 定位不到）；损失与指标 2 不对齐（排序项与 std 项权重为 0）；**两条基线的有效 batch 实际不齐（16 vs 8）**，口径清单打印的是配置常量而非 Trainer 实际值 |
| **v2** | 只动超参、best-checkpoint 准则、组内损失护栏，管线本身一行未改 | **4 项超参改动 3 项无效或有害**：`JOINT_EPOCHS=5` 把 DeBERTa joint 从 0.3790 打到 0.2002（Qwen 无感）；`WARMUP_RATIO 0.05`、`HUBER_DELTA 2.0` 零收益；`μ·L_std` 零收益且拖慢 21–40%。唯一正收益是 best-checkpoint 改用综合分（DeBERTa joint 从 −0.0137 救回 +0.2002）。根因判定：**不是「超参有毒」，而是 DeBERTa 在 fp32+Adafactor 下训练本身脆**；唯一系统性差异是梯度噪声尺度 |
| **v3** | 把三个指标各自落到显式损失项：`L_huber` + `L_order` + `L_mse` + `L_guard` + `L_xrank`，配 `AUTO_BALANCE` 在线反解权重；两次云端崩溃后修复 | 首次完整跑通 5×2 次运行，25 项口径自动 diff = 0，6 个设置的指标 2 全部非 nan、退化目标数全为 0。**Qwen joint = 0.4616 / 0.4168 / 0.9853（当前提交主线）**，DeBERTa joint = 0.3431 / 0.1956 / 0.9711。四个新机制的总账见下节。遗留：DeBERTa 在两个 nn 子集上相对 v1 崩塌 **−0.40** |

### 三代对照（指标 1 / 指标 2 / RMSE，均为 joint 运行）

| | v1 | v2 | v3 |
|---|---|---|---|
| DeBERTa | 0.3790 / 0.3402 / 0.9162 | 0.2002 / 0.0690 / 1.1237 | 0.3431 / 0.1956 / 0.9711 |
| Qwen | **0.4950 / 0.3864 / 0.8429** | 0.4999 / 0.3648 / 0.8459 | 0.4616 / 0.4168 / 0.9853 |

Qwen 相对 v1 的全部变化都落在噪声阈值内（Δ指标 1 ∈ [−0.051, +0.019]，阈值 0.065）。

### 创新性尝试与实测结论

只记录**改动本身有设计意图**的机制，无论结论好坏；常规工程不记。

| 机制 | 想法 | 实测结论 |
|---|---|---|
| `L_guard`（组内 std 的 hinge 下界） | 把每个目标的组内 std 顶在 κ 之上，防止指标 1/3 把组内方差压平导致 std ≡ 0 → 指标 2 = nan | ✅ **唯一确认正收益**：守住红线，6 设置指标 2 全非 nan、退化目标数全为 0。κ = 0.50 在 pv 上偏紧 |
| `L_xrank`（跨目标 std 大小序） | 指标 2 的可微代理，直接优化「谁更吃语境」的序 | ⚠️ **无可测收益**。激活率受限（联合运行里同子集目标凑不满对），nn 按设计置 0 |
| `L_order`（组内成对排序，只取符号） | 对独立噪声不敏感，抽取组内的相对次序信号 | ⚠️ **无可测收益**（全程生效，可配对为 0 的 batch 仅 0.3%）。日志里 `w_order=0` 是「快照只反映最后一个 batch」的记录缺陷，不是没生效 |
| `L_mse`（显式二次项） | 给 RMSE 一个专属项，避免 Huber(δ=1) 尾部走线性 | ❌ **疑似有害**：Qwen joint RMSE 0.8429 → 0.9853（差 0.142 > 阈值 0.046） |
| `μ·L_std`（组内 std 等值匹配） | 直接惩罚「预测组内 std ≠ 人工组内 std」 | ❌ **零收益 + 有害 + 昂贵**（DeBERTa 慢 21–40%）。方向错误：人工 std 掺着不可复现噪声。v3 直接删除该项 |
| `AUTO_BALANCE`（EMA 在线反解权重） | 不手调 λ/μ，按「该项应占总损失的百分比」在线反解实际权重 | 机制跑通、权重有限；⚠️ 「实际占比确实落在设定值附近」**未被独立验证** |
| best-checkpoint 选综合分 | `指标1 + 指标2`（nan 记 −1）选 epoch | ✅ v2 唯一正收益（Δ0.214）；⚠️ 但两个分量噪声量级差 2.4 倍（SD 0.023 vs 0.055），指标 2 主导决策 —— 在三代 30 次运行上重算，它吃掉了一个指标 1 相差 **0.1194** 的更好 checkpoint |
| float64 组统计矩 + std 三道安全网 | 组内 std 用「平方和 − 和的平方」还原在 fp32 下会灾难性抵消 | ✅ **根治 v3.1 的 NaN**：抵消误差 1.6% → 2.5e−9。配套 `preflight` 改走真实 `compute_loss` 反向，补上「只测 Huber ⇒ 新分项的 NaN 溜过去」的漏洞 |
| 目标级 cluster bootstrap 噪声阈值 | 在目标层重采样，量化「差多少才算真差」 | ✅ **方法论基石**：0.065 / 0.153 / 0.046 三个阈值直接判定了 v2 的 4 项改动全部无效 |

### 尚未解决的问题

| # | 问题 | 状态 |
|---|---|---|
| 1 | **DeBERTa 在两个 nn 子集上崩塌 −0.40**（噪声阈值的 6 倍） | 根因已锁定：**有效 batch 从 v1 的 16 掉到 8**（v1 两条基线本就不齐）。修法是两条基线同步提到 16（micro-batch 8 + 梯度累积 2，零显存代价）—— **未落码** |
| 2 | best-checkpoint 准则等权相加，噪声大的指标 2 主导决策 | 建议改 z 分数空间求和 `指标1/0.023 + 指标2/0.055 − 指标3/0.046` —— **未落码**（v2 提的 `−RMSE/5` 也从未落地） |
| 3 | **官方测试集推理 + zip 打包** | **未实现**，是通往合法提交的唯一硬阻断（测试集没有 `*Avg` 列，现有载入逻辑会 `KeyError`） |
| 4 | `loss_term_weights` 只记录最后一个 batch 的快照 | 会误导诊断（`w_order=0` 假象），应改全程 EMA —— 未落码 |
| 5 | `de-nn` 成分预切分、`en-pv`/`de-pv` 形态分析器补齐定位 | 未做；`de-nn` 修饰语列长期是短板 |
| 6 | 消融（`L_mse` / `L_xrank` / `AUTO_BALANCE` 逐项关闭）、按目标 5 折交叉验证 | 未做 |
